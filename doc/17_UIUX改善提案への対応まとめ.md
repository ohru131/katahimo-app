# UI/UX改善提案への対応まとめ

先方(株式会社キューテスト 中原様)から 2026-09-03 に受領した改善提案
`doc/16_UIUX改善提案_2026-09-03.html` への対応記録。

**提案どおりに直した点は書かない**(原本を見れば分かるため)。ここにまとめるのは
**提案と違うやり方にした点**と、**まだできていない点**だけ。

## 前提: どこを直したか

提案書はGAS版 `index.html` を読んで書かれているが、**直したのは `packages/web`(React版)**。

- `reference/gas-childcare-visit-app/` は参照用のスナップショットで、ここを直しても稼働中の
  GAS版には反映されない(`doc/10_GAS版連携の制約と方針.md` 参照)。
- 稼働中のGAS版そのものを直す必要がある場合は、GAS側プロジェクトでの別作業になる。

## 提案と違うやり方にした点

### 1. フォントは同梱しない(提案: BIZ UDPGothic + Zen Maru Gothic を読み込む)

**やったこと**: webフォントを読み込まず、`font-family` の先頭にUD書体を並べて、端末に入って
いればそれを使う指定にした(`"BIZ UDPGothic", "UD デジタル 教科書体 NP-R", "Hiragino Sans",
"Noto Sans JP", "Yu Gothic", "Meiryo", sans-serif`)。英数字専用だった Outfit は外した。

**理由**: 日本語のwebフォントは1書体あたり約1.3MB。本文400/700と見出し700の3書体で
アプリの配信物が約4MB増える(実測 388KB → 9.7MB)。現場はモバイル回線で、オフライン前提の
PWAとして端末に持たせる作りなので、この増分は割に合わない。

**影響**: BIZ UDPGothic はWindows 10以降に標準で入っているので、PC(事務局)ではUD書体になる。
iOS/Androidでは Hiragino Sans / Noto Sans JP 系になり、丸ゴシックにはならない。
読みやすさの改善は書体より **本文16px・行間1.6・コントラスト** で効いているため、
実用上の差は小さいと判断した。書体をどうしても揃えたい場合は、使う文字だけに絞った
サブセットを自前で作れば数十KBに収められる(別途作業)。

### 2. 出勤簿の「🔄 最新にする」は読み直しまで(提案: カレンダーとの差分確認まで)

React版には**カレンダーと見くらべる処理が無い**(下記「まだできていない点」)。ボタンは提案
どおり1つに統合したが、動作は出勤簿の読み直しまで。成功時のお知らせも
「出勤簿はカレンダーと同じです」ではなく **「出勤簿を最新にしました」** にした
(見くらべていないのに「同じです」と言うと嘘になるため)。

差分確認を差し込む位置は `packages/web/src/attendance/AttendanceCalendar.tsx` にコメントで残した。

### 3. 「毎晩、自動で最新になります」は出していない

夜間の自動取り込みがまだ動いていない(`packages/worker` は outbox ミラー送信のみ)。
代わりに **「ここに出るのは、保存した出勤簿の記録です。直したいときは、日にちを押してください。」**
とした。夜間同期が入ったら提案書どおりの文面に戻す(コードにコメント済み)。

### 4. 「先月より前の記録は見るだけです」は入れていない

サーバー側(`PUT /api/attendance/day`)に月による編集制限が無く、実際には編集できてしまう。
「見るだけ」と書くと嘘になるため入れていない。制限が必要ならAPI側の対応が先。

### 5. 日本語のボタンは横に並べず縦に積む

提案書のモックは2ボタン横並びだが、実機幅390pxで確認したところ
「📍 今いる場所から」「👤 お客様の情 報」「💡 書き方のヒ ント」「🖼️ 写真から選 ぶ」が
折り返して読めなくなっていた。文言を削るより縦に積むほうが確実なので、日本語ラベルの
ボタンは縦積みを既定にした。

### 6. 日報画面の下部固定バーは主ボタンを全幅にした

提案書は「取り消しは左・グレー、進むは右・青」。ただし横に割ると
「✨ AIに日報を書いてもらう」が2行に折り返す。主ボタンを全幅の1行目、「閉じる」をその下段に
した(閉じる導線はヘッダーの「✕ 閉じる」にも残してある)。

### 7. 領収書一覧の見出しは「この月の領収書 合計」

提案は「今月の領収書 合計」。月を選べる画面なので、先月を選んだときに「今月」と出るのを避けた。

### 8. 事故報告タブの並び替えは限定的

「メモ → AI → 結果」の順は入れたが、入力欄そのものの構成は既存のまま。AIが8項目に分配する
仕組みのため、欄を分解すると保存内容が壊れる。

## まだできていない点(このアプリに機能が無いもの)

| 提案書の項目 | 状況 |
| --- | --- |
| 出勤簿とカレンダーの差分確認・差分モーダルの文言 | React版に未移植。`doc/10` の「カレンダー連携の移行計画」参照 |
| 毎晩の自動取り込み | worker に未実装 |
| 「📅 一括反映(管理者用)」 | React版に該当機能なし |
| 「未登録顧客名(空白で顧客指定なし)」 | React版に該当欄なし |
| 「保存されていない入力内容があります(○○様分)」 | React版に該当機能なし |
| 天候トグルの hover 問題 | React版の天候は4択トグルではなく自由入力のため該当なし |
| 週リストの「・移動 18分」 | `GET /api/attendance/week` の戻り値に移動時間が無いため出せない。出すならAPI側の対応が必要 |

## 事務局(齋野様・土居様)に確認が必要な文言

| 箇所 | いま入れている仮の文言 | 確認したいこと |
| --- | --- | --- |
| 日報の星評価 | ⚠️ きょうヒヤッとした度合い (PSI) | PSI の正式な定義・日本語名 |
| 日報の星評価 | 😊 きょうの働きやすさ (従業員満足度(ES)) | 略号の併記はこの形でよいか |
| 今月のまとめ | 基準のきょりを超えた回数 | 何の基準か(1日の移動距離か、1区間か) |
| ログイン | 番号をメールで受け取る / このパスワードにする | 実行中の表示(「…しています…」)の言い回し |
| これまでの記録 | ⚠️ ヒヤッとした度合い / 😊 働きやすさ | 幅の都合で「きょう」を落とした短縮形でよいか |

## 検証したこと

- `pnpm lint` / `pnpm typecheck` / `pnpm test`(766件) すべて通過。
- デモビルド(ブラウザ内PostgreSQL)を実機相当の幅390pxで起動し、ログイン・きょうの予定・
  お客様一覧・出勤簿・日報画面を実際に描画して確認した。上記5・6はその確認で見つけた崩れ。
